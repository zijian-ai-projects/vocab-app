# Windows V1.4.3 新词标签小补丁 / DSH 0.1.10 检查

日期：2026-11-17。Windows 程序版本继续为 **1.4.3**；发行 ZIP 与包内顶层目录统一命名为 `VocabApp-1.4.3-windows-x64`。DSH 继续为 **0.1.10**。

## 结论与修复范围

- 新词点“认识”，在反面点“选错了”，再次出现时左上角显示 **新词**。
- 直接点“不认识”的新词重现、选择题模式的 Lv0 重现也显示 **新词**。
- 已学旧词到期仍显示 **复习**；旧词改判保留作答前等级，按原规则在 300 秒后复习。
- 不迁移、清空或重新计算任何个人记录；不调整重现间隔、每日额度或记账。
- DSH 0.1.10 **未复现同类问题**。未修改 DSH 运行代码、版本、发行包或本机安装。

## 根因证据

此前 Windows ZIP 的嵌入代码与修复前源码一致，包括快照恢复与改判逻辑。实际改判已正确恢复 `st=new / lv=0 / due=null`，没有把新词升级为旧词。

错误在 [Windows 学习状态标题](<../app/main.py#L3782-L3793>)：旧判断只把 `kind == new` 显示成新词，其余一律显示复习，因此把队列中 `retry` 这一种“尚未认识的新词重现”错误归类。此次仅把 `new` 和 `retry` 均显示成新词，保留 `review` 的复习标题。

[DSH 标题逻辑](<../dsh-plugin/lib/host/engine.js#L1473-L1477>) 本来就只把 `review` 显示成复习。真实 Engine 动作证明改判、重现和重启均保持新词；客户端使用该 `studyStatus` 字段，没有另行按 retry 改为复习。

- 标题动作测试采用真实原生 Qt Card，其中标题方法来自待验 EXE 的嵌入代码；它不是在冻结进程内部自动点击按钮的端到端测试。另有实际便携 EXE 启动/关闭验证。
- 全部记录路径及旧迁移候选在进入 UI 测试前重定向到合成路径，不打开个人学习记录。
- 没有在无开发环境的干净 Windows 机器验证；EXE 的实际 Authenticode 状态为 `NotSigned`，不承诺免 SmartScreen 提示。
- 既有 DSH Web GUI 需要认证，本次没有完成登录态浏览器实点，不把 Engine 或 Hook 测试冒充浏览器端到端。
- 没有重跑全部 29 个历史 Windows 清理入口，也不宣称历史 7 个既有失败已修复。
